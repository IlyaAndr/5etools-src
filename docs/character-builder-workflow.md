# Разработка через последовательные pull request

## Ветки

- `main` — исходная основная ветка репозитория; в текущем репозитории ветки `master` нет.
- `character-builder` — общая ветка разработки, созданная от актуального `origin/main`.
- `character-builder-01-model` и следующие ветки — небольшие изменения для одного PR с базой `character-builder`.

Следующую ветку создаём от обновлённой `character-builder` после принятия предыдущего PR. Если предыдущий PR ещё на ревью, независимую работу можно готовить локально; цепочки зависимых открытых PR по умолчанию не создаём.

## Цикл работы

Заголовки и описания всех pull request пишем на английском.

1. Выбрать небольшой законченный результат из плана, обозначить объём PR.
2. Поручить реализацию подагенту в рабочей ветке.
3. Основной агент проверяет изменения, запускает подходящие тесты и исправляет найденные проблемы. При необходимости привлекается отдельный агент для независимого ревью.
4. Опубликовать PR в `character-builder`, описав результат, ограничения и выполненные проверки. В GitHub Actions запускаются проверки модуля.
5. Передать ссылку пользователю для ревью. Замечания можно оставлять в GitHub или в чате; основной агент вносит исправления в тот же PR.
6. Сливать PR после явного одобрения пользователя. Автоматическое слияние не включаем. `main` не обновляем в рамках этого цикла.

Основной агент и подагенты используют один GitHub-аккаунт. Агентское ревью отражаем в описании PR; отдельное формальное одобрение собственного PR от того же аккаунта не подаём. Пользователь может изучить Files changed, оставить комментарии и одобрить слияние в чате.

## Начальная очередь PR

1. **Формат сохранения персонажа.** Версионированный документ, разделение решений и игрового состояния, строгая граница JSON-импорта, два неполных примера, тесты и этот процесс ревью. Полные расчёты D&D сюда не входят.
2. **Преобразование данных и контрольные результаты.** Минимальный каталог нужных сущностей, проверенные дополнения, гном и тифлинг, результаты для уровней 1/3/5 и основания расчётов.
3. **Ранний онлайн-лист и PDF.** Вывод контрольных результатов по шаблону скилла и проверка A4.
4. **Создание воина.** Общие расчёты и пошаговые выборы.
5. **Магия и создание колдуна.** Источники магии, инвокации и способы сотворения.
6. **Трекер и хранение.** Изменение игрового состояния, отдых, локальные персонажи, импорт/экспорт через готовый контракт.
7. **Повышение уровня и правки.** История решений и проверка зависимостей.
8. **Виды PHB 2024.** Все десять видов и их варианты по отдельному разделу плана; при необходимости разделить на несколько PR.
9. **Остальные классы и уровни.** Небольшими PR по семействам механик из плана.

Это порядок результатов. Границы следующих PR уточняются после ревью предыдущего, чтобы сохранять удобный для проверки объём.

## Проверки первого модуля

```bash
npm ci
npx --no-install vet-eslint js/character-builder test/jest/character-builder
npm run test:character-builder
```

Общий набор unit-тестов запускается через `npm run test:unit -- --runInBand`. План разработки находится в `docs/character-builder-development-plan.md`.
